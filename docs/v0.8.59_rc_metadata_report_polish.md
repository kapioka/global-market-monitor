# v0.8.59 RC Metadata / Report Polish

## Purpose

v0.8.59 is a small release-candidate polish pass before any tag creation. It keeps the RC review bundle metadata aligned with the requested version and makes suspicious domestic metric display safer for beginner-facing report readers.

## Metadata polish

- `logic_review_questions.md` now uses the bundle `--version` value in its heading.
- Diagnostic bundle smoke for `v0.8.59` must still include:
  - `project/hindenburg_omen.py`
  - `project/tests/test_hindenburg_omen.py`
  - `docs/v0.8.57_hindenburg_omen_display_monitor.md`
  - `project/chatgpt_diagnostic_bundle.py`
  - `project/tests/test_chatgpt_diagnostic_bundle.py`

## Report polish

Domestic metrics with suspicious-data limitations are not shown as ordinary adopted risk metrics in the beginner-facing report.

Handled limitations include:

- `split_or_discontinuity_suspected`
- `suspicious_price_move`
- `risk_signal_excluded`

When these limitations are present, report display uses wording such as:

- `12週変化: 異常値疑いのため非採用`
- `最大DD: 異常値疑いのため参考外`

The limitation text remains visible for review.

## Non-impact boundary

This polish does not change:

- `final_action`
- production `buy_readiness_score`
- buy blocker logic
- buy decision card logic
- decision-boundary experiment behavior
- threshold JSON
- reliability policy
- CI configuration
- dependencies
- Hindenburg Omen display-only boundary

No tag, push, or GitHub Release is created in this Goal.
