# v0.8.57 Hindenburg Omen Display-Only Signal Monitor

## Purpose

v0.8.57 adds a display-only Hindenburg Omen monitor for supplemental US market breadth visibility.

It answers:

- whether the signal is currently triggered or active
- when it triggered
- which active periods were opened or extended
- which criteria passed, failed, or were unknown
- which data limitations prevent a confirmed reading

## Non-decision boundary

This monitor must not affect:

- `final_action`
- `buy_readiness_score`
- buy decision card scoring
- buy blocker logic
- decision-boundary experiment behavior
- threshold JSON
- reliability policy

The report wording treats the monitor as a supplemental market breadth signal. It is not a crash prediction and is not investment advice.

## Data source policy

The monitor uses distribution-safe inputs only.

Supported inputs, in priority order:

- optional manual CSV: `project/manual_sources/hindenburg_breadth.csv`
- optional automatic CSV source: `hindenburg_omen.auto_csv_url` in `project/config.yaml`
- optional environment fallback: `HINDENBURG_BREADTH_CSV_URL`
- built-in provider attempt chain for diagnostics and future automatic acquisition:
  - `wsj_market_diary`
  - `barchart_market_momentum`
  - `marketwatch_us_market_data`

The manual CSV is optional and must not be committed.

If the manual file is present, it takes precedence. If the manual file is absent and an automatic CSV source is configured, the monitor fetches that CSV on each report build and runs the same parser and criteria calculation.

If no manual file or automatic source is available, the context returns:

- `status: manual_file_missing`
- `current_signal: unavailable`
- no active notification
- data limitation text in the report

The implementation does not require API keys, paid data dependencies, scraping, or inference from a small ETF list. Automatic sources must provide a CSV with the same schema as the manual file. A small ETF list is not treated as a substitute for NYSE market breadth.

Configured HTTP/HTTPS CSV sources are downloaded to a local cache before parsing. Direct production `pandas.read_csv(url)` loading is not used for Hindenburg Omen. Query strings and tokens are redacted from report-facing source labels.

The built-in provider chain records sanitized attempt results but does not bypass login, browser verification, CAPTCHA, private endpoints, or access controls. If all built-in candidates are unavailable, manual CSV and configured static CSV modes remain supported.

## Local SQLite state

The monitor stores local state per user in SQLite. The default location is under the user's application data directory:

- `%LOCALAPPDATA%/GlobalMarketMonitor/hindenburg_omen/hindenburg_omen.sqlite3`

Test and advanced runs may override this with:

- `HINDENBURG_OMEN_DB_PATH`
- `HINDENBURG_OMEN_DATA_DIR`

SQLite stores:

- normalized daily input rows
- daily calculation results
- current update state
- schema migration version
- provider health

The mutable database is not stored in the generated report directory.

## State model

The report context preserves the previous output keys and adds explicit update state fields:

- `UNINITIALIZED`
- `UPDATING`
- `CONFIRMED`
- `NO_UPDATE`
- `STALE`
- `INSUFFICIENT_HISTORY`
- `GAP_BLOCKED`
- `INVALID_DATA`
- `UPDATE_FAILED`
- `MIGRATION_REQUIRED`

Acquisition failure, parsing failure, calculation failure, and history gaps do not become `not_triggered`. When a previous confirmed value exists, update failure preserves that value and sets `is_previous_confirmed_result: true`.

## Calculation definition version

The compatibility definition is recorded as:

- `hindenburg_legacy_compat_v1`

Daily calculation results store:

- `definition_version`
- `denominator_method`
- `uptrend_method`
- `mcclellan_method`

## Manual CSV columns

Required for parsing:

- `date`
- `new_highs`
- `new_lows`
- `advancers`
- `decliners`

Recommended for confirmed detection:

- `nyse_index`
- `mcclellan_oscillator`

When `mcclellan_oscillator` is absent or blank, the monitor derives it from `advancers - decliners` using a 19-day EMA minus a 39-day EMA once at least 39 rows of advance/decline history are available.

Optional:

- `unchanged`
- `total_issues`
- `index_50d_ago`
- `index_above_50d`
- `source_note`

## Detection criteria

A day is confirmed as triggered only when all required criteria pass:

- uptrend: index above 50 trading days ago, above 50-day average, or `index_above_50d` is true
- new highs percent >= 2.8
- new lows percent >= 2.8
- McClellan Oscillator < 0
- new highs are not more than twice new lows

If uptrend or McClellan data is unavailable, the day is unconfirmed and does not produce a confirmed trigger.

## Active periods

Default active window:

- `30` days after each trigger

Period rules:

- a trigger opens an active period
- a later trigger within the active window extends the period
- a trigger after the prior active period ended starts a new period

## Report behavior

When active, the report shows:

- `Hindenburg Omen が点灯中です。`
- `これは米国市場幅の分裂を確認する補助指標です。`
- `単独では売買判断に使いません。`

When inactive:

- `Hindenburg Omen: 点灯なし`

When unavailable:

- `Hindenburg Omen: 未取得`
- `市場幅CSVが未設定のため判定できません。`

## Sample-only behavior

Sample-only does not fabricate market breadth values.

If no manual CSV exists, sample-only shows the monitor as unavailable/manual missing. Triggered and non-triggered cases are covered by tests using fixtures.
