# v0.8.51 Decision Boundary Experiment

## Purpose

v0.8.51 adds an experimental comparison payload for testing whether Japan-resident integrated risk context should ever influence decision boundaries.

The experiment is disabled by default and display-only.

## Payload

The report adds:

```text
decision_boundary_experiment
```

Main fields:

- `enabled: false`
- `baseline.final_action`
- `baseline.buy_readiness_score`
- `experimental.adjusted_buy_readiness_score`
- `experimental.supplemental_warning_level`
- `experimental.suggested_adjustment`
- `diff.score_delta`
- `diff.action_changed`
- `must_not_affect_production_default`

## Baseline Boundary

The baseline remains the production report:

- `final_action` from the buy decision card.
- `buy_readiness_score` from the existing readiness score calculation.

The experiment reads these values after the buy decision card is built. It does not write back to the card.

## Experimental Boundary

The experimental score applies a small supplemental discount based on `japan_resident_integrated_risk_context.combined_context_level`:

- `normal`: 0
- `watch`: -4
- `caution`: -8
- `block`: -12
- `unavailable`: 0

This is intentionally conservative and does not change production behavior.

## Non-Impact Boundary

v0.8.51 does not change:

- `final_action`
- `buy_readiness_score`
- threshold JSON
- reliability policy
- buy blocker logic
- buy decision card logic
- buy window / candidate thresholds
- risk label definitions
- CI, scripts, or dependencies

## Report Display

Markdown shows the baseline versus experimental score comparison.

The standard HTML risk-context hub shows an "実験比較" row when the payload exists.

## Deferred

The following are intentionally deferred:

- Enabling the experiment by default.
- Applying the experimental score to `buy_readiness_score`.
- Applying any integrated context to `final_action`.
- Changing thresholds or reliability policy.
