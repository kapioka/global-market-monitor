# v0.8.60 RC Final Polish

## Purpose

v0.8.60 is a final local RC polish pass. It tightens report-facing data-quality wording and manual Hindenburg Omen CSV handling without changing production decision logic.

## Suspicious domestic metrics

Domestic market metrics that carry suspicious-data limitations are not presented as ordinary adopted report metrics.

Handled limitations:

- `split_or_discontinuity_suspected`
- `suspicious_price_move`
- `risk_signal_excluded`

Report-facing text uses:

- `12週変化: 異常値疑いのため非採用`
- `最大DD: 異常値疑いのため参考外`

The original limitation remains visible. Structured metric payloads may still carry raw values for diagnostics, but beginner-facing reason text suppresses them.

## Hindenburg Omen stale handling

The Hindenburg Omen monitor now distinguishes:

- `data_latest_date`
- `as_of_date`
- `latest_trigger_date`
- `active_until`
- `is_active_as_of_latest_data`
- `is_currently_active`
- `stale_data`

If manual breadth CSV data is older than the local stale threshold, the report does not show a confident current active signal. It uses wording such as:

- `Hindenburg Omen: データが古いため現在点灯は未確定`
- `市場幅CSVの最新日が古いため、現在の点灯状態は判定できません。`

## Hindenburg CSV validation

Manual CSV rows are rejected as `parse_error` when required breadth values are impossible or invalid, including:

- negative `new_highs`, `new_lows`, `advancers`, or `decliners`
- `advancers + decliners <= 0`
- invalid date values
- nonnumeric `mcclellan_oscillator` when present
- nonpositive `nyse_index` or `total_issues` when present
- `new_highs` or `new_lows` exceeding `total_issues`

Invalid data cannot produce a confirmed Hindenburg Omen trigger.

## Diagnostic bundle

The default diagnostic bundle filename now follows the requested `--version`, for example:

- `project/diagnostics/chatgpt_logic_review_v0.8.60.zip`

## Non-impact boundary

This polish does not change:

- `final_action`
- production `buy_readiness_score`
- buy blocker logic
- buy decision card logic
- decision-boundary experiment behavior
- threshold JSON
- reliability policy
- Hindenburg Omen display-only boundary
- CI configuration
- dependencies

No tag, push, or GitHub Release is created in this Goal.
